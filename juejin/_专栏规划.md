# 掘金专栏规划：「手写 Vue3 内核」

## 1. 定位（一句话）

> 跟着一个 208 测试全绿的自研 mini-vue 工程，把 Vue3 的响应式、渲染器、编译器、内核补全与打包**亲手重写一遍**，每篇讲透一个面，并把「真正踩过的坑」翻开给你看。

**差异化**（与市面源码解析文的区别）：
- 不逐行解注释，而是「设计动机 → 最小实现 → 可复现验证 → 真实踩坑」；
- 有配套工程（TypeScript + pnpm，`pnpm test` 全绿），读者可以边读边跑；
- 每篇结尾给「自查三问」，把阅读变成自测。

## 2. 读者画像

| 人群 | 诉求 |
|---|---|
| 用过 Vue3 组合式 API 1-2 年的工程师（主） | 「ref/nextTick/keyed diff 背后是什么」 |
| 转前端 / 备战 Vue 原理面试 | 系统性补原理 + 能自圆其说地讲出来 |

前置要求：会写 Vue3、见过组合式 API；不需要会编译原理/Proxy 细节（文内展开）。

## 4. 每篇的结构模板（统一手感）

1. **导语**：读者画像 + 本篇一句话收获
2. **为什么需要它**：先立问题，再给方案
3. **关键实现**：代码节选（首行注释标工程位置）+ 白话解释
4. **动手验证**：最小可运行示例（配 `pnpm test` 或浏览器玩法）
5. **真实踩坑**：1-3 个，写根因（坑 = 读者未来会撞的墙）
6. **自查三问**：3 个判断题，参考答案藏文后（评论互动抓手）

## 5. 发布节奏建议（掘金连载）

- 首日：导读 + 01 同时发（两条互链）；
- 之后每 1-2 天一篇，保持「按顺序读」的追更感；
- 每篇文末预告下一篇钩子；article 内嵌官方源码链接（github.com/vuejs/core）增强可信；
- 暖场话术：可配「兴趣投票」（如 04 篇 Transition/KeepAlive 与 编译优化谁先谁后）制造评论互动。

## 6. 质量门槛

- **准确性**：每篇由 reviewer 抽查 2-3 个断言回源码核对（本系列稿件已安排）；
- **自包含**：全文无「阶段/gate/check 命令/仓库内部路径」等内部视角，读者不需要我们仓库的 legacy 知识；
- **可复现**：文中验证示例必须能在配套工程跑通（208 测试对标其一）。
