# 掘金专栏规划：「手写 Vue3 内核」

## 1. 定位（一句话）

> 跟着一个 208 测试全绿的自研 mini-vue 工程，把 Vue3 的响应式、渲染器、编译器、内核补全与打包**亲手重写一遍**，每篇讲透一个面，并把「真正踩过的坑」翻开给你看。

**差异化**（与市面源码解析文的区别）：
- 不逐行解注释，而是「设计动机 → 最小实现 → 可复现验证 → 真实踩坑」；
- 有配套工程（TypeScript + pnpm，`pnpm test` 全绿），读者可以边读边跑；
- 每篇结尾给「自查三问」，把阅读变成自测。

## 2. 读者画像

前置要求：会写 Vue3、见过组合式 API；不需要会编译原理/Proxy 细节（文内展开）。

## 4. 读者心智模型与写作原则（一切文章服务于此）

**读者是谁（一句话）**：会写 Vue3、组合式 API 顺手，但把框架当"魔法"——知道 `ref(0)` 会触发更新、`v-for` 能渲染，却说不清"到底是哪一行代码完成了这件事"；想听完一篇后自己也有能力重讲一遍。

**他缺什么 / 我们要给什么**

| 读者的真实缺口 | 我们的解法 |
|---|---|
| 只见过"魔法结果"，没见过"魔法机制" | 每篇从他写过的日常场景开头（改 data → 页面自己变），先复现"为什么会是这样"再揭机制 |
| 术语一多就弃读 | 新术语第一次出现先给一句人话定义，之后全篇复用，绝不先甩名词再解释 |
| 代码堆叠会淹掉因果 | 代码是**论据不是正文**：贴代码前一句话说明"这段解决什么"；片段 ≤ 15 行；注释写**意图**而非复述 |
| 全程被教育会疲劳 | 通篇第二人称"你"：用提问带节奏（"你现在想——怎么知道该更新哪个节点？"），每节收口一个微型结论 |
| 读完仍拼不成道理 | 每篇末"三步走复盘"：机制怎么串起来 → 你自己复刻时第一行写什么 → 用一句话讲给同事听 |

**五条硬原则（写稿前必查）**
1. 更难的放后面：从熟悉场景（组件/模板/页面）逐层进到底层机制（Proxy/状态机/链表），不第一段上硬菜。
2. 一个概念一次讲透，不跨篇硬拆。
3. 遇到"官方源码里其实更复杂/有更优解"就一句话点到，不展开打断主线。
4. 自查三问的问题，答案必须已埋进前文（不用谜语，鼓励读者回找）。
5. 验证示例要么读者能照抄跑（给 `pnpm` 一键），要么把"预期你能看到什么"写清楚。

- **准确性**：每篇由 reviewer 抽查 2-3 个断言回源码核对（本系列稿件已安排）；
- **自包含**：全文无「阶段/gate/check 命令/仓库内部路径」等内部视角，读者不需要我们仓库的 legacy 知识；
- **可复现**：文中验证示例必须能在配套工程跑通（208 测试对标其一）。
