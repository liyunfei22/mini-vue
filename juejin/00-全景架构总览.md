# 手写 Vue3 内核（总览）：先看整片森林，再进每一棵树

> 在看反应式、渲染器、编译器之前，先花十分钟把「Vue 到底是怎么工作的一整张图」拿下。
> 这篇不讲某个 `ref` 具体怎么实现，只回答三个问题：**Vue 整体怎么转的？为什么拆成这些包？它们怎么协作？**

## 导语

很多原理文章一上来就钻进 `effect.ts` 或 `baseHandlers.ts`——读者很容易「见树不见林」：单个文件都懂，合起来却说不清一帧渲染是怎么发生的。

本系列有一个配套的「 mini-vue 内核」工程（TypeScript、208 个测试全绿），我们照它重写官网结构。这第一篇就是给整套工程画一张**总装图**，让你带着图去读后面的 01–05。

## 一句话，Vue 怎么工作

```
"<div>✕{{ count }}</div>"
   │ 编译期（可提前，也可能运行时做）
   ▼
render 函数（返回虚拟节点 vnode）
   │ 渲染器执行
   ▼
真实 DOM
   ▲
   │ 每次 reactive 状态变化 →（调度器合并成一次微任务）→ 重新执行 render → 精准 patch DOM
响应式状态（ref / reactive）
```

关键就一句：**数据一变，触发「重跑视图描述」，渲染器只把变化的部分差量打到 DOM**。编译期负责把模板变成"视图描述函数"，运行时负责"执行描述 + 差量更新"。

## 为什么 Vue 要拆成这些包？（layering 的动机）

官方 monorepo 的全景（也是本系列配套工程镜像的拆分）：

```
shared          基础工具（类型判断、电容、ShapeFlags/PatchFlags）
reactivity      响应式：reactive/ref/effect/computed/effectScope
runtime-core    渲染逻辑：vnode/组件/渲染器/调度器/watch（与平台无关）
runtime-dom     浏览器适配：nodeOps/patchProp/createApp
compiler-core   编译逻辑：parse/transform/codegen（与平台无关）
compiler-dom    浏览器专属编译：isNativeTag 等 + compile
vue             聚合入口：createApp + 运行时编译器
```

拆包不是凭感觉，是为了四个工程目标：

1. **平台无关的核心可复用**。`runtime-core` 不知道什么是 DOM——它只认 `RendererOptions` 接口（`createElement/insert/patchProp/...`）。换一套 nodeOps，同一个渲染器就能跑在 canvas、Weex、SSR 模拟 DOM 上。
2. **编译/运行可分离**。只想用运行时（模板预先编译好）的买家，引 `vue/runtime-*` 就不必背编译器体积；编译器这层纯粹是"模板→函数"的字符串处理。
3. **树摇友好**。按需 import，只引用的部分进包（配合 `sideEffects: false`）。
4. **团队/心智边界清晰**。每个包一个 topic，测试也都是每个包自己的。

## 每个包具体干什么

| 包 | 干的活 | 你会在里面找的符号 |
|---|---|---|
| `shared` | 类型判断、常量（ShapeFlags 位图、PatchFlags）、`makeMap` 等 | `isObject` `hasChanged` |
| `reactivity` | 把数据变响应式、把副作用绑上依赖 | `ref` `reactive` `computed` `effect` `watch` |
| `runtime-core` | 渲染器 + 组件模型 + 调度 | `createRenderer` `h` `nextTick` `transition` |
| `runtime-dom` | 浏览器桥接：DOM 操作与属性/事件打补丁 | `createApp` `vShow` `vModel*` |
| `compiler-core` | 「模板字符串 → render 函数源码」的状态机与代码生成 | `baseParse` `transform` `generate` |
| `compiler-dom` | 浏览器模板语法（标签白名单、`v-model` 等） | `compile` |
| `vue` | 把上两家缝起来 | `createApp(template)` 才可用；`compileToFunction` |

## 它们怎么协作（这是最关键的一张图）

1. **模板字符串**在 `vue` 聚合包里经由 `compileToFunction` = `compiler-dom.compile` + `new Function` 现场变成 **render 函数**；
2. `createApp` 把根组件（含 render 或 template）挂给 `runtime-dom.createRenderer` 产生的渲染器；
3. **组件挂载 = 一条渲染 effect**：`instance.update = effect(componentUpdateFn, { scheduler })`——响应式依赖一变，调度器把它送上微任务队列批量执行；
4. 渲染 effect 重跑 `render` → 新 vnode → 渲染器 `patch` 新旧 → keyed diff / block 快速路径 → **差量改 DOM**；
5. `reactivity` 负责「谁依赖了谁」的表，`runtime-core` 负责「怎么把新 vnode 变 DOM」，`compiler-core` 负责「模板怎么变成 vnode 描述」。三者通过**薄薄的协议**咬合：渲染器只认 vnode 与宿主接口，编译器只产 vnode 构造调用。

依赖方向是铁律、单向的（绝不让上游依赖下游）：

```
shared → { reactivity, compiler-core }
reactivity → runtime-core → runtime-dom
compiler-core → compiler-dom
(以上) → vue
```
