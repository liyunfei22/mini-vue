# 专栏规划 v2：「实现 Vue 3 内核」（juejin2）

> 本文件是 v2 版专栏的协作计划，取代 `juejin/` 下 v1 版本的地位。v1 稿件保留存档，不再发布。

## 1. 修订背景：v1 的三个问题

| # | 问题 | v2 对策 |
|---|---|---|
| 1 | 文风口语化、带明显「AI 生成感」：通篇第二人称、反问句推进、比喻堆砌、互动小模块（自查三问/三步走复盘）喧宾夺主 | 全面改为技术书行文：以论证结构推进，人称克制，术语严谨（规范见 §4） |
| 2 | 内容以仓库笔记为底稿改写，缺少对官方文档的对齐：术语、行为描述无基准 | 确立三源基准（§3），所有行为断言可回溯到官方文档或 vuejs/core 源码 |
| 3 | 组织方式是「学习过程流水账」变体，缺少设计层面的叙事 | 参照《Vue.js 设计与实现》的组织方法：问题 → 权衡 → 实现 → 分析 |

## 2. 定位与读者

- 定位：跟随一个自研 mini-vue 工程，**重新实现** Vue 3 的响应式系统、渲染器、编译器、内核补全与构建流水线；每篇讲透一个子系统的设计动机、实现细节与同官方实现的差异。
- 读者：有 1 年以上 Vue 3 使用经验的前端工程师；不要求读过编译原理或框架源码。
- 产出预期：读完能独立说清「`state.count = 1` 到 DOM 更新之间发生的每一件事」，并具备从零复刻最小内核的能力。

## 3. 内容基准（三源，按优先级）

1. **官方文档（cn.vuejs.org）**：术语与对外行为的唯一基准。写作前先读对应页面，文中术语与文档措辞保持一致。对应关系：

   | 篇目 | 文档页面 |
   |---|---|
   | 00 架构 | 深入响应式系统、渲染机制（渲染管线三阶段：编译/挂载/更新） |
   | 01 响应式 | 深入响应式系统（Proxy、track/trigger、WeakMap 结构、副作用定义）；响应式 API：核心（ref 深层转换、computed、watch flush） |
   | 02 渲染器 | 渲染机制（虚拟 DOM、挂载、更新/比对）；深入响应式系统（组件渲染副作用） |
   | 03 编译器 | 渲染机制（模板的静态分析优势） |
   | 04 内核补全 | Transition（六类名与 JS 钩子）、KeepAlive（include/exclude/max、activated/deactivated）、表单输入绑定（v-model 修饰符与元素-属性-事件组合） |
   | 05 构建 | 无直接对应页（工程实践） |

2. **vuejs/core 源码（v3.5.x，本地 `third_party/vue-core`）**：实现真相。凡写「官方实现如何」，必须核对源码文件后落笔，并给出文件路径。
3. **《Vue.js 设计与实现》（霍春阳著）**：组织方法参照——问题动机、多方案权衡、渐进式实现、优劣分析。仅借鉴行文结构，不复述书中内容；需要提及时按「参见该书第 X 篇/章」标注（第一篇「概述」、第二篇「响应式系统」、第三篇「编译器」）。

配套工程（本仓库）提供全部代码样本与测试：`packages/*`（约 8500 行 TypeScript）+ `pnpm test`（全套行为测试）。

## 4. 文风规范（硬性，逐条过检）

**叙述**
- 以「我们」或无主语句式推进论证；第二人称「你」每篇至多个别处出现，禁止作为行文节奏。
- 禁止反问句连用、感叹号、空洞设问开头（「你有没有想过……」一类全部禁止）。
- 每段一个论点，论点句在段首；节与节之间由问题演化衔接，不靠过渡套话。

**术语**
- 首次出现给「中文（英文）」并给一句定义，例：依赖收集（dependency tracking）——在属性被读取时记录当前副作用的过程。此后全篇统一用词，不换同义词。
- 与官方文档措辞对齐：副作用（effect）、订阅者（subscriber）、补丁标记（patch flags）、缓存静态内容/静态提升（static hoisting）、区块（block）、树结构打平、比对（diff/patch）。

**代码**
- 一律引用本仓库实现，标注仓库路径（如 `packages/reactivity/src/effect.ts`）。
- 每个代码块之前用一两句说明它解决的子问题，块之后逐点分析关键行；长度以说清为准，不设上限，但不得包含与当前论点无关的代码。
- 示意性伪代码必须显式标注「示意」；与源码有出入的节选必须标注「节选，完整实现见 X」。

**禁用清单**
- emoji、颜文字、网络用语。
- 口语词：「坑」→「易错点/陷阱」；「魔法」→「隐式机制」；「拍脑袋」→「直觉方案」。
- 互动模块：「自查三问」「三步走复盘」「讲给同事听」等一律不出现；收尾用「小结」+「延伸阅读」。
- 营销式小标题、空洞总结句（「以上就是本文的全部内容」）。

**事实性**
- 行为断言必须可回溯（文档页 / core 源码 / 本仓库测试）；无法核实的推断要显式标注「推断」或删除。
- 涉及版本差异（3.4/3.5 响应式重构等）须查发布说明或源码后落笔。

## 6. 协作流程

```
写作（单篇成稿，遵守 §4 规范）
  → 校对 A（事实核对：抽查每篇 ≥3 个断言，回官方文档/core 源码验证；核对全部代码节选与仓库源码一致）
  → 校对 B（文风检查：逐条对照 §4 规范与禁用清单）
  → 人工终审（作者通读，决定是否发布）
  → 发布（掘金连载，1–2 天一篇）
```

- 校对 A/B 发现的问题分两级：事实错误（必须修）、文风偏差（修至符合规范）。终审只做取舍，不做重写。
- 任一环节的修改都要回归检查：不引入新断言、不破坏术语一致性。

## 7. 质量门槛

- 每篇事实断言 100% 可回溯；代码节选与仓库当前实现一致。
- 术语与官方文档一致；全系列术语表统一（见各篇首次定义处）。
- 自包含：不依赖仓库内部过程视角（阶段编号、打卡、评审记录）；读者只需 Vue 3 使用经验。
- 可复现：文中验证步骤给出可执行命令与预期结果。
