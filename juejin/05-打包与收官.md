# 05-打包与收官：三种产物与一条 source，把内核变成能发的库

> 写在前面：如果你会写 Vue3、想看原理，这篇讲一个库怎么从 TS 源码变成 npm 上能直接消费的产物。前几篇我们复刻了响应式、运行时、编译器，正缺「发货」动作；本篇做收尾——参考 vuejs/core 的构建骨架（https://github.com/vuejs/core），把子包打成 esm-bundler / cjs / global 三种形态加一份 d.ts，顺带解决 __DEV__ 注入、source 条件、双包后缀这几个「发货」才撞得到的坑。

## 为什么需要打包

库与业务代码最大的区别：业务代码只服务一个入口、一种环境，库要同时服务三类消费者——现代前端要 ESM、老 Node 要 CommonJS、`<script>` 直引要 IIFE 挂全局，加 TypeScript 用户要的 d.ts——于是有了官方「一个包多份产物」的格局，真 Vue 的 dist 里同时躺着 `vue.esm-bundler.js`、`vue.cjs.js`、`vue.runtime.global.prod.js`。我的复刻过程照抄这套骨架：一份配置声明式生成。

## 关键实现

### 构建入口：遍历包目录的编排脚本

脚本只做几件事：扫出带 package.json 的子包、重建 dist、逐包 spawn rollup 并注入 TARGET 与 NODE_ENV。

```js
// scripts/build.js —— 遍历 packages，逐包 spawn rollup
const targets = readdirSync(PACKAGES_DIR)
  .filter((dir) => {
    try { readFileSync(`${PACKAGES_DIR}${dir}/package.json`, 'utf-8'); return true }
    catch { return false }
  })
  .filter((t) => all || targetArgs.some((a) => a.startsWith(t)))

for (const t of targets) {
  rmSync(`${PACKAGES_DIR}${t}/dist`, { recursive: true, force: true })
  mkdirSync(`${PACKAGES_DIR}${t}/dist`, { recursive: true })
  await run('npx', ['rollup', '-c', '--environment', `TARGET:${t},NODE_ENV:${NODE_ENV}`])
}
```

滚动起来的是「一份共享配置 + 每次注入不同 TARGET」——monorepo 构建的核心形态。

### 格式与命名：一个函数翻译「产物三形态」

rollup 支持 `es` / `cjs` / `iife`，但「格式→文件名→导出形态」的映射要自己定义。`esm-bundler` 这名字来自官方——「给 bundler 用的 ESM」，区别于 `<script type="module">` 直用的原生 ESM，差别在 `__DEV__` 这类构建期常量是否保留。

```js
// rollup.config.js —— 由 TARGET 决定包，formats 决定产物后缀
const outputName = (f) => {
  const prod = isProd ? '.prod' : ''
  if (f === 'esm-bundler') return `packages/${TARGET}/dist/${pkg.name.replace('@mini-vue/', '')}.esm-bundler${prod}.js`
  if (f === 'cjs') return `packages/${TARGET}/dist/${TARGET}${prod}.cjs`
  if (f === 'global') return `packages/${TARGET}/dist/${TARGET}.global${prod}.js`
}

export default formats.map((f) => ({
  input: `packages/${TARGET}/src/index.ts`,
  output: {
    file: outputName(f),
    format: { 'esm-bundler': 'es', cjs: 'cjs', global: 'iife' }[f],
    exports: 'named',
    name: f === 'global' ? name : undefined, // name = buildOptions.name || 'MiniVue'
  },
  plugins: [
    nodeResolve({ exportConditions: ['source'], extensions: ['.ts', '.js'] }),
    esbuild({ define, target: 'es2018', minify: isProd, treeShaking: true }),
  ],
}))
```

`formats` 取自各包 `buildOptions.formats`：shared 只发 esm-bundler + cjs；vue 包三份全发，global 挂 `MiniVue`。

### __DEV__：构建期注入的开关

库源码里到处是「只有开发才需要」的校验告警，混进产物会撑大生产包。起初我想照官方一样「构建期注入开关」：源码里把 `__DEV__` 当普通常量、写死为 `true`（保证类型检查与测试独立跑通），让 `EMPTY_OBJ` 在 dev 冻结、prod 不冻结。但这里藏着一个机制坑——见下。

```ts
// packages/shared/src/index.ts —— 源码态 __DEV__ 恒为 true
export const __DEV__ = true

export const EMPTY_OBJ: { readonly [key: string]: any } = __DEV__ ? Object.freeze({}) : {}
export const EMPTY_ARR: readonly any[] = __DEV__ ? Object.freeze([]) : []
```

真正的开关在 build 端——esbuild 插件收到 define 后，把源码里**表达式位置**的 `__DEV__` 全替换成 `true` / `false` 字面量：

```js
// rollup.config.js —— 构建期把 __DEV__ 替换成字面量
const define = {
  __DEV__: isProd ? 'false' : 'true',
  'process.env.NODE_ENV': JSON.stringify(NODE_ENV),
}
```

⛰️ **机制真相**：esbuild 的 `define` 只替换**自由（全局）标识符**，对「模块内的本地声明」`export const __DEV__ = true` **不生效**。实测 `--prod` 后产物里 `__DEV__` 仍以 `!0`(=true) 存在、告警分支原封不动，dev/prod 里 `EMPTY_OBJ` 都是 `Object.freeze({})`——当前的 dev/prod 差异其实只来自 **esbuild 压缩**。

想让构建端真正换个语义，`__DEV__` 必须保持「自由标识符」：(a) 源码用 `declare const __DEV__: boolean` 只声明不绑定，构建端再 define / feature-flags 注入；(b) 或用词法替换插件并在替换时避开声明行（官方就是这么做的）。这是本 mini 的一个**已知取舍**：告警分支在 prod 产物里仍在，后续可切到官方同款 feature-flag 方案。

### source 条件：跨包直接从源码吃

七个子包互相 import，vue 聚合其余五个。若 `import '@mini-vue/shared'` 落到 shared 的 dist，就陷入「构建顺序」鸡生蛋问题，依赖链一长只能上拓扑排序。解法是 exports 里的 source 条件 + nodeResolve 的 `exportConditions: ['source']`：解析时优先命中 `"source"` 分支，跨包直接吃兄弟包的 **src/index.ts 源码**，与产物解耦；rollup 最终打的是「vue + 全部依赖源码」的单一 bundle，构建顺序问题消失。

```json
// packages/vue/package.json —— exports 的多条件解析
{
  "exports": {
    ".": {
      "types": { "source": "./src/index.ts", "default": "./dist/vue.d.ts" },
      "source": "./src/index.ts",
      "import": "./dist/vue.esm-bundler.js",
      "default": "./dist/vue.cjs"
    }
  }
}
```

`types` 里还嵌套一层：支持 source 时连类型都指向源码，否则回落到 `dist/vue.d.ts`。

### 类型声明的两段式：tsc 产碎片 + rollup 捆成单文件

d.ts 分两段生成。第一段 `tsc -p tsconfig.build.json` 只发声明不产 JS（`emitDeclarationOnly` 开关在配置里），声明落进中间目录 `temp/types`；第二段用 rollup-plugin-dts 把碎片捆成单文件。

```js
// rollup.dts.config.js —— 第二阶段：将分散的 d.ts 捆成一个入口
export default {
  input: `temp/types/${TARGET}/src/index.d.ts`,
  output: { file: `packages/${TARGET}/dist/${TARGET}.d.ts`, format: 'es' },
  plugins: [dts()],
}
```

两段式的好处：tsc 产出忠于源码的碎片声明零风险，「捆包」再折叠成干净的类型入口。

## 动手验证

构建流程最小可跑通：

```bash
node scripts/build.js shared            # dev：__DEV__=true，产出 shared.esm-bundler.js / shared.cjs
node scripts/build.js shared --prod     # prod：__DEV__=false + esbuild 压缩，产出 *.prod.js
node scripts/build.js vue --with-types  # 追加 tsc + rollup-plugin-dts，生成 vue.d.ts
```

对比同一行代码在两份产物里的差异，就是 `__DEV__` 注入的现场：

```js
// dist/shared.esm-bundler.js（dev）
const __DEV__ = true;
const EMPTY_OBJ = Object.freeze({}) ;

// dist/shared.esm-bundler.prod.js（--prod，仅压缩）
const __DEV__ = !0;
const EMPTY_OBJ = Object.freeze({}) ;
// 告警分支仍在（define 对本地绑定不生效，见上文·机制真相）
```

再换不同运行时消费 vue 包产物，三种形态各得其所：

```js
import { createApp, version } from './packages/vue/dist/vue.esm-bundler.js' // bundler
const { createApp } = require('./packages/vue/dist/vue.cjs')               // Node 老项目
// vue.global.js：<script> 引入后全局挂 MiniVue
```

## 真实踩过的坑

**坑一：`"type": "module"` 下 CJS 产物被 Node 当成 ESM。** 子包都标了 `"type": "module"`。第一次我把 CJS 产物命名成 `vue.js`，Node 按 ESM 解析，`module.exports` 直接抛错。根因：Node 按就近 `"type"` 解析 `.js`——`.js` 是 ESM、`.cjs` 是显式 CommonJS、`.mjs` 是显式 ESM。

**坑二：`--environment` 用逗号切 KV，塞多值会丢。** 起初想一条命令把参数传全，结果 rollup 按逗号拆开 KV，复合值被截断，包名/环境对不上号。根因：`--environment` 是「逗号分隔的 K:V」单层结构，逗号进不了值。最后改成每次 spawn 只传一个 TARGET。

**坑三：忘了开 source 条件，跨包解析落到不存在的 dist。** 有一版没把 `exportConditions: ['source']` 写进 nodeResolve，rollup 按 import → default 命中 `./dist/x.esm-bundler.js`，而那一刻 dist 尚不存在，`UNRESOLVED_IMPORT` 刷屏、产物断链。加回 source 条件才根治；再在 onwarn 里过滤 `CIRCULAR` 与有意保留的跨包 `UNRESOLVED_IMPORT`，日志才安静。

## 自查三问

1. 包声明了 `"type": "module"`，CJS 产物为什么必须叫 `.cjs`？倒进老 Node 会怎样？
2. 源码里 `__DEV__` 写死为 `true`，esbuild 的 define 为什么对它不生效（本地绑定 vs 自由标识符）？想让 dev / prod 真正换语义，`__DEV__` 应该如何声明？
3. `exports` 里的 `source` 条件解决了什么构建顺序问题？去掉它会怎样？
